# 诊断日志与问题反馈（0.6.1）

## 怎么反馈

1. 在出问题的电脑上退出旧版，用 0.6.1 或更新的 EXE 替换原文件，保留 app-data。
2. 打开新版，重新执行一次会出问题的操作。日志无法补录旧版已经发生的过程。
3. 左侧进入“诊断与日志”，点击“导出诊断文件”，选择保存位置。
4. 将生成的一个 JSON 文件发到协助开发的对话中。可附一句当时做了什么，便于对应操作。

诊断文件只保存在本机，没有自动上传、邮箱发送或遥测服务。

## 软件打不开时

如果程序已经执行到初始化阶段，会在 EXE 旁 app-data/logs/latest-diagnostic.json 保存自动诊断。可直接发送这个文件。启动错误分类也会写入 startup-error.log。

若 Windows 在程序执行之前就阻止启动、目录不能写入或进程被直接终止，可能没有新的诊断文件。这时发送系统提示截图，并说明软件版本。报告中的生成时间和 appVersion 可用于确认是否为本次故障。

## 收集范围

- 软件版本、构建模式、Windows 构建号、进程/系统架构、WebView2 与 SQLite 版本。
- 数据库 schema、完整性检查状态、影片/目录/失败任务/缺图和未知时长数量等统计，不包含作品资料。
- 操作名称、开始/结束时间、耗时、错误分类、有限的系统错误码和代码位置。
- 前端异常只保留已知异常类型及应用代码行列坐标，不收集完整调用栈。

**不保存或导出：** 视频、字幕、封面、数据库文件、片名、笔记、完整本地路径、来源网址、账号/令牌、操作参数或原始报错文本。错误码也经过白名单/格式限制，读取日志导出时会再次校验。

未知错误可能只留下操作与代码位置，个别问题仍可能需要补充步骤或截图；不承诺任何故障都能仅凭日志解决。

## 日志保留

结构化日志位于 app-data/logs/diagnostic.jsonl，最多 3 份轮换文件，每份约 256 KiB。启动时清理超过 7 天的这些日志，导出仅保留近 7 天且最多 2,048 条事件。latest-diagnostic.json 是另一个最多 128 条近期事件的自动报告：关键操作开始前记录检查点，错误时节流更新，退出时再更新。

诊断预览可以查看将导出的安全字段。正常导出会重新采集当前状态，近期操作可能比预览时多几条。导出只创建新的 .json 文件，不覆盖已有文件，不改变数据库或媒体。
